Pose Estimation

Estimated time: ~20 minutes Helpful background: Data Ingestion (introduces pose files and keypoints) Related: Precomputed Tracking & QC (quality control - which rests entirely on the confidence idea below)

This page is a deep dive - optional background, not a required stop in the main sequence. It stands on its own if you want to understand what pose estimation and confidence actually are, whether or not you have read the other pages.

This is a conceptual notebook. We do not train a pose model here. The goal is to understand where pose estimation sits in the pipeline, what a keypoint confidence actually is, and when you would need to generate keypoints yourself - so the quality-control work on the Precomputed Tracking & QC page makes sense.

Scope note. This course works with pre-computed pose data: the Kumar Lab already ran a pose model on every video, and its output is the same pose data described on the Data Ingestion page. Generating pose from raw video (training your own model with a tool like SLEAP or DeepLabCut) is a large topic of its own and is out of scope for the hands-on part of this course. We cover it conceptually here and will point you to the tools that may be helpful in practice.

Where Pose Estimation Sits¶

The full path from a raw recording to a quantified behavior:

raw video  -->  pose estimation  -->  feature extraction  -->  behavior classifier  -->  ethograms
                  (keypoints)            (JABS)                   (XGBoost)
                  ^^^^^^^^^^^^^
                  THIS notebook's topic

Pose estimation is the step that turns pixels into coordinates: for each video frame it predicts the location of a fixed set of anatomical landmarks (keypoints). Everything downstream - the features JABS computes, the behavior classifier, the ethograms - is built on top of those keypoints.

The barrier. A dataset of raw videos is not directly usable by JABS; you first need keypoints. Some public datasets (like the one in this course) ship pre-computed keypoints, but most do not. Producing them means labeling frames, training a model, and running inference - real work that requires compute and expertise.

What Is Pose Estimation?¶

A pose estimation model takes one video frame and outputs, for each keypoint, a predicted location and a confidence value. In this dataset there are 12 keypoints (nose, ears, neck, paws, spine, tail), and the output per frame is the same structure described on the Data Ingestion page:

  • points - the predicted (y, x) pixel location of each keypoint
  • confidence - how certain the model is about each keypoint

The model does not "know" anatomy; it learns from labeled examples to associate image patterns with keypoint locations. The interesting question for using its output is: how much should I trust each predicted point? That is what confidence captures, and to read confidence correctly you need to know where it comes from.

How Confidence Maps Work (the key idea)¶

Modern pose models do not directly regress an (x, y) number. For each keypoint the network outputs a confidence map (also called a heatmap): a 2D grid, the size of the frame, where each cell holds the model's belief that the keypoint is there.

  • The predicted location is the peak (argmax) of that map.
  • The confidence is the height of that peak.

So a confidence value is not an abstract score - it is literally how tall the most likely spot is:

  • A sharp, tall peak means the model is sure: one clear location. High confidence.
  • A flat, diffuse map means the model has no clear answer. Low confidence.

This is why a threshold like 0.3 is meaningful: below it, the map had no real peak, so the predicted point is little better than a guess. Precomputed Tracking & QC uses exactly this idea to decide which frames and keypoints to trust. Let's make it concrete.

# Why: illustrate "sharp peak = high confidence, flat map = low confidence"
# with a synthetic example, before looking at any real pose data.
def confidence_map(peak_height, spread, size=64):
    """A toy 2D confidence map: a Gaussian bump of a given height and spread."""
    yy, xx = np.mgrid[0:size, 0:size]
    cy, cx = size / 2, size / 2
    g = np.exp(-(((xx - cx) ** 2 + (yy - cy) ** 2) / (2 * spread ** 2)))
    return g * peak_height


fig, axes = plt.subplots(1, 2, figsize=(11, 4.5))
for ax, (height, spread, label) in zip(
    axes,
    [(0.95, 3.0, "Sharp peak -> HIGH confidence (~0.95)"),
     (0.25, 14.0, "Flat, diffuse -> LOW confidence (~0.25)")],
):
    cmap_img = confidence_map(height, spread)
    im = ax.imshow(cmap_img, cmap="viridis", vmin=0, vmax=1)
    py, px = np.unravel_index(cmap_img.argmax(), cmap_img.shape)
    ax.scatter([px], [py], c="red", s=60, marker="x")
    ax.set_title(label)
    ax.axis("off")
    fig.colorbar(im, ax=ax, fraction=0.046, pad=0.04, label="map value")

From Map to (y, x, confidence)¶

In a real file you never see the full maps - they are huge (one grid per keypoint per frame). The model stores only the distilled result:

confidence map (per keypoint, per frame)
        |
        |  take the peak
        v
   (y, x) location  +  peak height (confidence)
        |
        v
stored in points (n_frames, 1, 12, 2) and confidence (n_frames, 1, 12)

That is precisely the poseest/points and poseest/confidence data described on the Data Ingestion page. Now let's look at how confidence actually varies across body parts in the real data.

Why Do Keypoints Differ in Confidence?¶

Look at your chart above. Two things are usually true:

  1. Everything is well above 0.3. This dataset's pose model is high quality, so on a clean session most keypoints sit near the top of the range (confidence here is a heatmap-peak value and can even slightly exceed 1.0). The 0.3 line is there for reference - you will see points dip toward it on hard frames, not as a session average.
  2. Some keypoints are consistently a little lower than others. The exact ranking varies by session, but the reason is always the same: how hard that landmark is to localize.
  • Parts that are large, high-contrast, and always visible from above (nose, neck, spine) tend to have sharp confidence peaks.
  • Parts that are thin, low-contrast, fast-moving, or easily occluded (the tail tip, and the paws when they tuck under the body) tend to have flatter peaks, so lower confidence.

Read your own chart rather than assuming a fixed order. The practical consequence: a feature that depends on a lower-confidence keypoint will be noisier, and you may want to filter or interpolate its low-confidence frames. That is the work of the Precomputed Tracking & QC page.

When Would You Generate Your Own Keypoints?¶

This course uses pre-computed pose, but in your own research you may not have that luxury. The decision:

Does your dataset already have pose keypoints?
  YES -> use them (as this course does)
  NO  -> Is your setup close to an existing model's training data?
           YES -> consider fine-tuning that model
           NO  -> label frames and train your own

A few tools can do this, and they all use the same confidence-map mechanism shown above, so the intuition transfers directly regardless of which you pick:

  • SLEAP (Pereira et al., Nature Methods 2022) and DeepLabCut are general-purpose, multi-species pose estimation tools - label a small number of frames, train a model, and run it across a full video.
  • The Kumar Lab's own mouse-tracking-runtime (the same pipeline that produced this course's keypoints) is another option if your animal is a mouse specifically. It is trained specifically for mice and may not generalize to other species or recording setups the way SLEAP or DeepLabCut's more general-purpose models can.

Training your own pose model is a substantial topic - compute, labeling effort, evaluation - and is beyond this module's hands-on scope, but you now understand what it produces and why confidence matters.

How this dataset's keypoints were made: the Kumar Lab produced keypoints using mouse-tracking-runtime, run on every open-field video, producing the same version-6 pose files described on the Data Ingestion page.

Challenge Questions¶

  • A keypoint's confidence map has two peaks of nearly equal height (for example, the model cannot tell the left paw from the right). What confidence would you expect, and what failure mode would that produce in the stored (y, x)?
  • You computed mean confidence per keypoint over a whole session. How might per-frame confidence tell a different story than the session average, and why does that matter for quality control?
  • Pose models are trained on a particular species, arena, and camera view. If you applied this dataset's model to a video of rats in a differently lit arena, which keypoints would you expect to degrade first, and how would the confidence values reveal it?
